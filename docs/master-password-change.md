# 主密碼更換與復原（R13）

本機、單程序／單 worker 個人版。這是「知道目前主密碼後更換」，不是忘記密碼時的解密重設；不更改 SQLite schema 或密碼欄位格式。

## 操作

1. 到「密碼保管庫 → 更換主密碼 → 開始更換主密碼」。已設定但尚未解鎖時也能操作，**仍必須重新輸入正確的目前主密碼**，解鎖 cookie 不能取代這項驗證。
2. 輸入不同的新主密碼及確認，16–1024 個 Unicode 字元，保留前後空白；不要把新舊主密碼存進專案備註。了解舊備份及全部連線鎖定的提醒後勾選確認。
3. 按「備份並更換主密碼」。成功會回到保管庫頁、清除目前 cookie，撤銷本 app 全部舊 session；用新主密碼重新解鎖。沒有自動維持解鎖或把新金鑰傳給瀏覽器。
4. 到「資料備份」查看／下載標示「主密碼更換前自動備份」的復原點，並另外妥善保管新舊主密碼。

繁中／英文、無 JavaScript 原生提交皆支援。輸入錯誤時展開原表單，但三個密碼欄位與確認勾選一律清空，必須重新輸入與確認；不寫瀏覽器儲存或 URL。網路中斷後不要盲目重送，先確認狀態；簽章提交識別會使同一已成功操作只返回結果，不再更換或建立第二份快照。

## 交易及競態界線

1. 檢查長度、確認、新舊不同及 UTF-8 格式；沿用解鎖的程序內限流，錯誤目前主密碼會計入同一個限制。超量或錯誤不建立復原點。
2. 取得資料庫排他維護權，先等待既有 HTTP 操作完成，期間新讀寫／解鎖回覆 503、不自動重播。這包含「已派生舊金鑰但還沒建立 session」的 HTTP 請求；它必須完成後才會開始更換。新端點只略過普通 DB admission，不略過 Host／來源／CSRF。
3. 在 `BEGIN IMMEDIATE` 同一交易內重新驗證舊主密碼，保留寫入鎖，以另一條唯讀連線的 SQLite backup API 建立及驗證**完整、尚未變更**的復原點。沒有從持有未提交寫入的連線直接 backup，避免等候自己；副本建立或驗證失敗不進行重新加密。
4. 產生新的 16-byte salt、32-byte 金鑰、驗證 nonce／密文；沿用已驗證的 KDF 參數，不在更換時靜默降低成本。逐筆解密並以新金鑰及 fresh nonce 加密，再驗證該筆可還原，最後更新 verifier／salt。包含正常、封存、垃圾桶中的全部加密帳號；沒有保存密碼的 metadata 紀錄保持不動。
5. 所有密文與 verifier 在同一交易提交；禁止內部重新加密回呼提前 commit／savepoint／attach。只改密碼密文及保管庫設定，帳號 metadata、專案更新時間、生命週期、匯出政策不變。
6. **仍在排他維護權內**撤銷全部舊 session，才重新開放請求。帳號新增／更新的金鑰取得也放進相同的 DB admission／寫入交易，避免直接服務呼叫在更換後寫回舊金鑰密文。

沒有將全部帳號明文先收集成清單；每筆處理後釋放參照。Python 不可變字串與加密庫暫存仍不保證安全抹除。更換不撤銷已收到的明文、下載檔或外部副本；跨分頁遮蔽沿用既有 BroadcastChannel／狀態輪詢，後端 session 才是授權判定，無 JavaScript 時不能保證即時遮蔽畫面。

## 失敗與復原

正常的解密／加密／寫入／提交失敗由 SQLite 交易 rollback 回復，不留下只改一半的密文或新 verifier；已完成的更換前快照保留。進入重新加密後的失敗會撤銷舊 session，錯誤回應不包含原始例外或任何密碼，確認狀態後可用舊主密碼重新解鎖並重試。

若 rollback 自身失敗、提交結果不明、失敗後 verifier 已不是舊值，或無法核對結果，系統**停止普通資料存取**，不聲稱已自動恢復，也不私自用整份副本覆寫可能已變動的資料。資料備份頁與既有復原點下載仍可用；請保留原檔和快照、停止 ProjMemo，依 [本機維運](local-operations.md)／[備份復原](backup-recovery.md) 的離線復原流程處理。不要刪除唯一副本、修改 salt 或只替換 verifier 來嘗試解鎖。

這不保證斷電／硬體故障／外部工具寫入／多程序的全部災難復原；仍禁止兩個程序共用同一 DB。排他 gate 與限流是本程序的協調，不是多人登入、跨 worker 鎖或離線防猜測保證。

## 舊備份與保留策略

快照名稱為 `projmemo-pre-vault-change-YYYYMMDD-HHMMSS-microseconds.sqlite3`，放在該 DB 的 `backups/`；只含原來的密碼密文，不保存主密碼或金鑰，其他專案與帳號欄位仍是明文。建立採獨占檔名，不覆寫舊復原點；復原點目錄若是連結會拒絕建立。

**更換前的每份備份繼續使用該份備份當時的主密碼。** 新主密碼無法解鎖舊備份。還原更換前的完整備份等同回到舊 salt／密文／主密碼與當時全部專案資料，不是只切回主密碼；還原後所有 session 仍會撤銷。

新類型已接入既有安全下載白名單與 R11 手動保留／清理。預設保留全部，沒有自動刪除、更名或重新加密舊備份；只有使用者預覽並確認清理後才可能刪除。持有舊備份和舊主密碼的人仍能解密那些舊資料；更換本機主密碼無法撤銷這種能力。

`tests/test_vault_rotation.py` 使用隔離假資料，涵蓋 DELETE／WAL、空保管庫、舊備份還原、非預設 KDF、Unicode／空白、全部生命週期、舊 session、共用限流、備份／中途／提交／rollback 故障、排他請求與服務層寫入競態、原生重試／防重播／CSRF／不回填及下載。`tests/browser/vault-rotation.spec.cjs` 驗證雙語、兩瀏覽器、無 JavaScript 及跨分頁遮蔽；不接觸正式資料。

密碼學呼叫沿用 [Cryptography AES-GCM 文件](https://cryptography.io/en/latest/hazmat/primitives/aead/#cryptography.hazmat.primitives.ciphers.aead.AESGCM)，交易語意依 [SQLite Transaction](https://www.sqlite.org/lang_transaction.html)。原 salt／主密碼及 15 分鐘界線見 [保管庫安全說明](vault-security.md)。
