# 搜尋與交接效率（R10）

維持個人桌面版、FastAPI／Jinja2／原生 JavaScript 與 SQLite v4。本項不改 schema、不新增套件，不影響既有密碼、匯出、備份與垃圾桶規則。

## 搜尋與篩選

首頁搜尋區為原生 GET 表單，繁中／英文及停用 JavaScript 都能使用。

| 條件 | 行為 |
| --- | --- |
| 搜尋範圍：專案基本資料 | 預設搜尋名稱、說明、標籤與專案負責人。 |
| 搜尋範圍：包含專案內容 | 除基本資料外，搜尋下列五類文字；不需要解鎖保管庫。 |
| 負責人 | 專案負責人中的一個完整名稱；`Ryan` 不會匹配 `Ryan2`。 |
| 標籤 | 一個完整標籤；`Python` 不會匹配 `Pythonista`。 |
| 交接進度 | 全部、尚有未完成項目、交接項目已全部完成、尚無交接項目。零項目不視為全部完成。 |

多個條件取交集。一般字詞是字面子字串，`%`、`_`、反斜線不是萬用字元；支援短中文片段，英文 ASCII 不區分大小寫，不提供正規表示式、搜尋語法或拼字修正。負責人／標籤以 Unicode casefold 比對，支援既有逗號、全形分隔符等格式，但不重寫舊值。字詞最多 256 字元，負責人／標籤各 1000 字元；空字元或超長值拒絕，不默默截斷。

五類內容的白名單：

- URL：標題、網址、備註。
- Markdown：標題、完整原始 Markdown（不受 UI 備註分頁限制）。
- 交接清單：標題、說明、負責人、備註。
- 環境變數：名稱、用途、存放位置／負責人。
- 帳號：名稱、主機／登入網址、資料庫、登入帳號、權限、用途、負責人及密碼存放位置說明。**不查詢密文、nonce、主密碼、驗證密文或解密金鑰，也不執行解密**。

內容搜尋以專案為結果，不列出本文片段、命中排序或個別備註定位；開啟專案後按原有內容區段與備註分頁閱讀。不對實際密碼提供搜尋；若使用者把密碼誤填在一般文字欄位，仍屬可搜尋的明文，因此請遵守欄位用途。

使用中、已封存、垃圾桶彼此隔離；垃圾桶即使 URL 指定 `search_scope=all`，仍回到基本搜尋，不以子內容的命中與否洩漏被隱藏的正文。垃圾桶只顯示既有專案 metadata 及交接數量，不新增內容入口。

每個分類的負責人／標籤建議只來自該分類的基本資料、最多各 200 個（先依專案 ID 讀取，再對已收集名稱排序），亦可手動輸入未列出的完整名稱。分類徽章仍是分類總數，結果數才受篩選影響。切換分類、卡片／清單與 10／20／50 分頁會保留條件；「清除篩選」保留分類、檢視與筆數，「重設列表」回到目前分類的卡片／10 筆並清空條件。

## 偏好及安全界線

沿用 `projmemo.listPreferences.v1`，舊四欄偏好仍可讀；只增加已套用且非預設的 `owner`、`tag`、`search_scope`、`handover`。空白的明確 URL 條件仍優先，裸首頁才還原偏好並回第 1 頁。封存／垃圾桶不覆寫使用中偏好；偏好讀取上限 4096 字元，壞值或 storage 不可用時走原生 URL，不保存頁碼、內容或草稿。

搜尋詞與負責人／標籤可能出現在本機 URL、瀏覽器歷史及上述 localStorage；不要輸入真實密碼或 Key，也不要隨意分享含敏感 metadata 的網址。搜尋不等於認證或多人權限隔離。

SQL 使用固定欄位白名單及參數。`EXISTS` 不會因多筆備註命中而重複專案；COUNT 和分頁在同一個讀取交易中。僅傳回目前頁的專案 metadata 與進度，沒有將全部子內容載入 Python。進度以兩個索引 COUNT 計算，不用五類 JOIN 造成數量倍增。

## 交接進度與未完成檢視

卡片、明細與內容頁顯示完成筆數／總數、向下取整的百分比及剩餘項目；零項目顯示「尚無交接項目」，不是 100%。明細清單可直接開啟「查看未完成項目」。

內容頁「全部交接項目／僅未完成」只改呈現，不刪除已完成項目。捷徑及標題旁兩處計數仍表示**全部交接項目數**，未完成數另列。勾選最後一項後保留未完成檢視、顯示空結果，仍可切回全部。

URL 使用 `checklist=pending#handover`；新增／編輯／切換完成狀態／錯誤回填及單次送出重播均保留此狀態。其他內容表單亦攜帶相同的非敏感 UI 隱藏欄位；備註換頁與筆數表單保留交接篩選，JavaScript 卡片／明細選擇亦帶入篩選連結。離頁仍受既有草稿保護。

普通／敏感 Markdown、PDF 及 SQLite 備份仍使用完整資料；不能把 `checklist=pending` 當作裁切匯出條件。垃圾桶繼續由 R09 阻擋內容讀寫與匯出。

## 量測與 FTS 決策

`scripts/benchmark_r10.py` 不接受 DB 路徑，先改指向 `TemporaryDirectory` 內的假資料，再啟動測試 app；結束還原環境變數、正常關閉並清除。每個情境預熱 1 次、取後 5 次中位數；測量 service 與 TestClient 完整 HTML 請求，**不是瀏覽器繪製時間或效能 SLA**。每個專案有 20 筆備註，其餘四類各 2 筆。量測前後以 SHA-256 確認 DB 未被搜尋改寫。

2026-10-16 Windows／Python 3.12.10／SQLite 3.49.1，本次第二輪結果：

| 專案／備註數 | 情境 | 命中專案 | Service 中位數 ms | HTML 中位數 ms |
| --- | --- | --- | --- | --- |
| 250／5,000 | 基本字詞 | 250 | 2.99 | 7.87 |
| 250／5,000 | 內容稀少命中 | 10 | 15.75 | 20.05 |
| 250／5,000 | 內容無結果 | 0 | 15.96 | 21.95 |
| 250／5,000 | 短中文字詞 | 250 | 4.72 | 8.20 |
| 250／5,000 | 組合篩選 | 2 | 4.53 | 7.09 |
| 1,000／20,000 | 基本字詞 | 1,000 | 6.45 | 10.54 |
| 1,000／20,000 | 內容稀少命中 | 40 | 35.76 | 40.40 |
| 1,000／20,000 | 內容無結果 | 0 | 59.73 | 58.11 |
| 1,000／20,000 | 短中文字詞 | 1,000 | 12.87 | 16.39 |
| 1,000／20,000 | 組合篩選 | 10 | 13.18 | 16.48 |

第一輪同一組 1,000 專案的內容服務中位數約 28–126 ms；兩輪波動不當作優化前後差異。第二輪每頁 10 筆的完整 HTML 約 11–21 KB。Query plan 使用生命週期索引及五類 `project_id` 索引縮小關聯掃描；`LIKE '%字詞%'` 本文仍須掃描，不宣稱 B-tree 已最佳化任意子字串。

另在**獨立記憶體 SQLite** 實測 FTS5 `unicode61`／`trigram` 原型，內容為「部署前先備份 release-marker」。字面子字串均命中；本例 `unicode61 MATCH` 不命中「署／部署／部署前／lease」，`trigram MATCH` 不命中「署／部署」，但命中三字「部署前」及英文中段「lease」。這是指定樣本的語意對照，不是與完整五類搜尋等價的效能比較。

決策：以目前個人版資料規模與短中文搜尋需求，**本輪不新增 FTS schema、觸發器或索引副本**。若未來實際資料成長造成明顯延遲，再量測短詞 fallback、CJK tokenizer、索引維護／還原／封存隔離成本，另設 migration；不能直接把 MATCH 當成現有字面搜尋的替代品。這是 R10 量測後的取捨，不把尚未導入的 FTS 宣稱為已交付。
