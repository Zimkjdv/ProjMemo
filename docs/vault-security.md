# ProjMemo 密碼保管庫與主密碼說明

本文說明 ProjMemo 如何使用主密碼與 salt 派生加密金鑰、如何判斷主密碼是否正確，以及解鎖逾時後會發生什麼事。

## 先說結論

- 主密碼不會保存到 SQLite，也不會被用來直接加密密碼欄位。
- SQLite 會保存隨機 salt、Argon2id 參數，以及一段由金鑰加密的驗證資料。
- 設定、解鎖或更換主密碼時，程式以「主密碼 + salt + Argon2id 參數」派生 32-byte 金鑰。
- 解鎖成功後，派生金鑰暫存在目前應用程式程序的記憶體，最多 15 分鐘；瀏覽器 Cookie 保存的是隨機 session token，不是主密碼或加密金鑰。
- 15 分鐘後 session 失效。再次使用保管庫時，重新輸入主密碼，程式便能用資料庫裡相同的 salt 和參數重算金鑰。

## Salt 和主密碼的關係

Salt（鹽值）是建立保管庫時由作業系統安全亂數產生的一段隨機資料。本專案目前使用 **16 bytes**，並將它保存於 SQLite 的 `vault_config.salt` 欄位。

概念上，金鑰派生可表示為：

```text
加密金鑰 = Argon2id(主密碼, salt, KDF 參數)
```

Salt 不是主密碼，也不是另外一組使用者需要記住的密碼。它可以和資料庫一起保存，不需要保密；它的用途是讓相同主密碼在不同保管庫中派生出不同金鑰，並使預先計算的密碼猜測表不容易重複利用。Salt 本身不會增加主密碼的秘密強度，也不能代替強而唯一的主密碼。

ProjMemo 將 Argon2id 的參數（記憶體用量、迭代次數、平行度）一併保存，解鎖時讀取這些參數，確保能以相同方式重算金鑰。

## 設定與解鎖流程

### 第一次設定

1. 使用者輸入主密碼（目前至少 16 個字元）。
2. 程式產生隨機 salt。
3. Argon2id 根據主密碼、salt 和 KDF 參數派生 32-byte 金鑰。
4. 程式用 AES-GCM 以該金鑰加密固定的驗證資料，將 salt、驗證密文、nonce 和 KDF 參數寫入 SQLite。
5. 實際帳號密碼之後也使用派生金鑰以 AES-GCM 加密後存進 SQLite。

### 之後解鎖

1. 使用者再次輸入主密碼。
2. 程式從 SQLite 讀取原本的 salt 與 KDF 參數，重新派生金鑰。
3. 程式嘗試用該金鑰解密驗證密文；只有解密成功且驗證內容正確，才接受主密碼並建立解鎖 session。
4. 若主密碼錯誤，解密驗證會失敗，程式拒絕解鎖。

因此，程式不必保存主密碼，也能在之後判斷輸入是否正確。Salt 固定保存在資料庫，是為了讓相同主密碼每次都能派生出相同金鑰；如果換成不同 salt，派生金鑰就會不同，既有密文也無法解開。

## 更換主密碼（R13）

保管庫設定頁新增「更換主密碼」，不論目前是否解鎖都必須重新驗證正確的舊主密碼，不能繞過舊密碼重設。系統先保存完整更換前快照，再於同一交易內產生新 salt／金鑰／驗證資料，逐筆重新加密所有帳號的實際密碼；沿用已驗證的 KDF 參數與 AAD 格式。全部提交後，在重新開放請求前撤銷所有舊 session，要求新主密碼再次解鎖。

一般失敗會交易回復；提交／rollback 結果無法確認時停止普通資料存取，保留快照供離線復原，不聲稱所有例外都已自動恢復。更換前備份仍需舊主密碼，更換不會撤銷外部副本或已取得的明文。流程、故障邊界與復原方法見 [主密碼更換與復原](master-password-change.md)。

## 15 分鐘逾時後

解鎖成功時，伺服器程序記憶體會保存派生金鑰，瀏覽器收到的是隨機、不透明的 session token。Cookie 設為 HttpOnly，且有 15 分鐘有效期限。逾時後，該 token 不再能取得金鑰，使用者必須重新輸入主密碼；程式再以資料庫中保存的 salt 和 KDF 參數派生並驗證。

session 的有效性以伺服器 monotonic 時鐘判定，讀取不會延長期限；重複解鎖成功會先撤銷同一瀏覽器的舊 token。每次 session 讀取／建立會清除全部過期項目，應用程式啟動期間另有每 30 秒的清理作業。最多保留 32 個 session，達上限先淘汰期限最早的一個，避免不必要的金鑰參照累積。這是 Python 物件參照清理，**不保證記憶體位元立即安全抹除**；進行中的操作也可能暫時持有自己的參照。15 分鐘是授權有效期限。

專案頁面顯示目前剩餘時間與本次到期時刻，保管庫設定頁顯示剩餘時間；重新載入都不會重設成 15 分鐘。`GET /settings/vault/status` 僅回傳狀態、剩餘時間、到期時刻、非授權用的 session 版本及匯出政策；禁止快取，不回傳 token、主密碼、金鑰或帳號密碼。前端倒數採本地 monotonic 計時並扣除狀態請求耗時，後端仍是有效性的判定來源。

保管庫設定頁以單一狀態徽章、大字 `mm:ss` 與剩餘進度條呈現同一個 session，不另開一個 15 分鐘計時器；專案頁原有的剩餘時間／到期時刻顯示維持不變。倒數不逐秒對螢幕閱讀器播報。無 JavaScript 時顯示載入當下的剩餘時間與明確提示，不宣稱畫面會自動更新；後端仍拒絕過期的密碼操作。

匯出保護的開關是原生 checkbox 加上 Switch 語意，整個標籤可點擊、可用鍵盤空白鍵操作。「目前」表示伺服器已儲存的政策，切換中的草稿另標示「尚未儲存」。啟用 JavaScript 時，沒有變更或切回原設定會停用儲存並提示「尚無變更」；原生無 JavaScript 表單保留可送出按鈕。單次送出、離開草稿保護及伺服器授權仍照常執行；鎖定時可關閉敏感匯出，開啟時必須先解鎖。一般 Markdown／PDF 匯出依舊不包含實際密碼，開啟政策不代表跳過敏感匯出的當次確認。

倒數到期會立即遮蔽已顯示密碼、使延遲 reveal 回應失效，停用密碼欄位並清空其中未提交的值，保留其他未儲存資料。前端在可見分頁每 10 秒重查狀態；重新取得焦點／可見時也會先遮蔽再確認。支援 BroadcastChannel 的同來源分頁會在保管庫頁載入或成功還原的返回頁通知其他分頁重查；不透過 localStorage 保存資料。session 版本改變（例如重新解鎖）、還原／鎖定或政策變動時，提示手動重新整理以取得最新操作，不自動重載並丟失草稿。狀態暫時不可讀時暫停密碼操作，待後端恢復後重新確認。沒有 JavaScript／BroadcastChannel 時，授權仍由後端檢查，但即時畫面同步能力有限。

伺服器重啟會清除程序內的 session。**僅限單程序、單 worker**：金鑰、清理作業與解鎖限流都在程序記憶體，不能直接增加多個 worker，也不要啟動兩個服務共用同一份資料庫。此設計適合目前的本機個人版，不代表已具備多人協作所需的身分驗證與授權。

## 忘記主密碼的影響

主密碼不會以明文保存，也沒有可供管理者讀出的副本。若忘記主密碼，程式無法從 salt 或驗證資料反推出主密碼或金鑰，因此已加密的帳號密碼將無法解密。SQLite 備份可以保留加密資料，但不能取代主密碼。

請將主密碼妥善保存在 ProjMemo 以外的安全位置，並定期備份 SQLite 資料。不要把主密碼寫進專案備註、Markdown/PDF 匯出檔或和資料庫放在同一位置。

## 安全界線

- Salt 和 KDF 參數不是秘密；取得 SQLite 的人仍可能嘗試猜測主密碼。Argon2id 會提高每次猜測的成本，但無法補救過短或常見的主密碼。
- 本機解鎖嘗試限制主要針對應用程式線上的反覆嘗試；若攻擊者取得資料庫副本，仍可在離線環境進行猜測。
- 非密碼欄位（例如帳號名稱、用途、負責人、Secret 存放位置）不屬於這個加密保管庫的密碼密文範圍，仍可能以一般資料形式存在 SQLite。
- Markdown/PDF 預設不匯出實際密碼；若使用者在設定中明確允許敏感匯出，產生的檔案會成為額外的明文資料副本，必須自行保護與刪除。
