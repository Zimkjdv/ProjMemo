# 備份預覽、保留策略與完整備份加密評估

R11 的現行操作與取捨，更新日期：2026-10-19。基本復原與故障處理見 [備份復原](backup-recovery.md)；本機單程序、單 worker 的限制不變。

## 還原：先預覽，再確認

1. 在「資料備份」選擇 SQLite 檔案，按「預覽備份」。上傳仍限制 100 MB；先檢查完整性、schema、關聯、索引及保管庫參數。這一步不升級上傳檔，也不替換目前資料。
2. 比較目前資料與備份的 schema 版本、專案總數及三種分類、五類內容數量、保管庫是否設定、加密密碼筆數與含密碼匯出政策。舊版另標示還原時會升級至目前 v4。
3. 核對範圍：這是整個 SQLite 資料庫替換，包含封存、垃圾桶、帳號與全域保管庫／匯出設定，不是專案合併。預覽只顯示數量與設定狀態，不列出專案內容、帳號或密碼。
4. 勾選理解替換範圍，輸入固定大寫 `RESTORE`，按「確認還原全部資料」。這些檢查由後端執行，停用 JavaScript 仍可操作。
5. 系統取得既有排他作業權、等待已接納的請求完成，先建立還原前快照，再比較預覽時的資料狀態。若有變更，回覆 409，不替換、不撤銷目前解鎖；已建立的復原點仍保留。請重新預覽，不能強行覆蓋新工作。
6. 未變更才撤銷全部解鎖 session、替換、逐版升級及驗證；失敗沿用原有自動回復與阻止不安全存取的機制。成功後須以備份所屬的原主密碼解鎖。

狀態比對以一致快照及串流邏輯指紋進行，包含 schema、資料型別與長度，不受 WAL／頁面布局影響；文字中的 NUL 也不會被截斷。指紋僅作狀態變更偵測，不是簽章或備份來源證明。只在本機程序內協調作業，不能防止外部 SQLite 工具或另一個程序在比較後寫入。

預覽不解密帳號密碼，也無法在不知道原主密碼時證明密文可以解開；不要把「驗證通過」理解為已驗證密碼。若備份開啟含密碼匯出政策，確認頁另外警告；匯出仍需解鎖與逐次確認。

## 暫存與確認的生命週期

- 每份計畫使用不可猜測的隨機 token，綁定 CSRF 瀏覽器、目前資料庫路徑與操作種類，有效 10 分鐘。token 只在 POST 表單，不放 URL、日誌或瀏覽器儲存。
- 最多保留 4 份待確認計畫；不能以清理 token 執行還原，亦不能由另一個瀏覽器、另一份 DB 或已消耗的 token 重送操作。確認的取得與消耗為原子操作；這不是跨重啟的操作歷史。
- 「取消預覽」立即嘗試移除該份暫存上傳。到期後拒絕操作，由每 30 秒清理工作或下一次存取移除；正常停止也會清理。還原確認無論成功或失敗，都消耗 token 並清理暫存。
- 暫存檔位於目前資料庫旁，以 `mkstemp` 建立，沿用該目錄的作業系統權限。密碼欄位仍是密文，其他內容仍可讀；不保證防止同一個 Windows 帳號或系統管理員讀取。
- 若外部檔案鎖造成刪除失敗，程序記錄不含內容的警告，保留重試紀錄並計入容量，下次清理再嘗試。強制終止、斷電或持續鎖定仍可能留下 `.projmemo-upload-*.sqlite3`；不要把正常清理當成安全抹除保證。
- 重新啟動後確認失效，需重新上傳。異常留下的檔案不會在下一次啟動被盲目批次刪除；停止服務、核對檔案來源並保留需要的副本後，再人工處理。
- 預覽頁切換語言會回到可安全 GET 的備份首頁，不對 POST-only 網址重新導覽或把 token 放入網址。若離開時未取消預覽，原暫存按到期機制清理；要繼續還原須重新上傳。

## 復原點保留策略

預設「全部保留」。儲存設定、重新整理、建立復原點、還原或重新啟動，**都不會自動刪檔**。

選擇自訂時可設定：

| 設定 | 範圍 | 效果 |
| --- | --- | --- |
| 至少保留最新份數 | 1–500 | 依檔案修改時間排序，保留最新 N 份；同時間以檔名排序 |
| 最短保留天數 | 0–3650 | 不清理未滿指定天數的檔案；0 表示不另加天數限制 |

兩項保護同時適用。例如 N=10、天數=30：只有「不是最新 10 份，而且已滿 30 天」的檔案才會成為候選。不是每個來源各保留 N 份，而是合併還原前／永久刪除前清單計算。

設定以原子替換保存在目前資料目錄的 `backups/retention-policy.json`，不新增 schema／依賴，也不包在 SQLite 下載中；還原資料庫不覆寫主機的保留政策。同一資料目錄的復原點及政策共用，請勿把多個獨立資料庫混放在同一資料目錄。設定損壞時停止清理，但備份頁及既有復原點下載仍可使用。

### 手動清理

1. 儲存策略，再按「預覽可清理的復原點」。沒有候選就顯示未刪除任何檔案，不產生刪除確認。
2. 核對每一份候選的檔名、時間與大小；可直接下載，先將需要的檔案另存安全位置。
3. 勾選理解永久刪除，輸入大寫 `DELETE` 後才會清理。取消、過期、只儲存策略都不刪除檔案。
4. 後端取得排他作業權，重新核對策略、候選檔名／大小／修改時間／檔案識別，以及保留範圍內至少有一份通過既有驗證的復原點。任何變更先拒絕，不沿用過期清單。
5. 一次最多 100 份，超過 2000 份須先備份再離線整理。刪除遇到檔案鎖或權限錯誤就停止並顯示已刪除／尚未清理數量；不假裝整批成功，也不能回復已刪除的檔案。

只處理 `backups/` 直層、嚴格符合 `projmemo-pre-restore-*.sqlite3` 或 `projmemo-pre-delete-*.sqlite3` 時間戳格式的普通單一連結檔案。跳過 symlink、junction、hard link 與未知檔名；復原點目錄本身為 symlink／junction 時拒絕操作。不遞迴清理 `backups/migrations/`，也不碰下載副本、上傳暫存、正式 DB、日誌或 `.venv`。

清理只移除已確認的檔案，不是安全抹除，也不會清除其他磁碟、郵件或雲端上的副本。請不要只保留同一磁碟的復原點；獨立備份及人工復原流程仍有必要。

## 程式呼叫與相容性

新的 UI 流程使用以下六個 POST，全部沿用來源／CSRF 保護；讀取或 GET 不會執行清理：

| 路徑 | 用途 |
| --- | --- |
| `/settings/backup/preview` | 上傳驗證、建立還原比較 |
| `/settings/backup/restore/confirm` | token、`acknowledged=yes`、`confirmation=RESTORE` |
| `/settings/backup/preview/cancel` | token 及 `kind=restore`／`cleanup`，取消計畫 |
| `/settings/backup/retention` | 儲存 `mode`、`keep_count`、`min_age_days` |
| `/settings/backup/cleanup/preview` | 列出候選，不刪檔 |
| `/settings/backup/cleanup/confirm` | token、`acknowledged=yes`、`confirmation=DELETE` |

token 欄位名為 `preview_token`。原 `/settings/backup/restore` multipart 上傳 API 保留相容性，仍是呼叫即執行還原，不要求新 UI 預覽；程式客戶端必須自行完成範圍確認。原下載 API 與其 HTTP 契約不變。

每個 HTTP 請求會先隔離繼承的資料庫 ContextVar，避免 keep-alive 回應完成時啟動的新請求借用上一個請求的 admission／maintenance；既有請求內的巢狀服務仍共用同一作業權。這不是跨程序鎖，也不是 Windows Proactor 停機問題的修復。

## 完整備份加密評估與本輪決定

**目前下載、復原點與上傳仍是標準 SQLite；只有實際密碼欄位加密，其他資料不是全檔加密。** 保管庫主密碼／解鎖金鑰不在備份內。R11 原驗收是「評估完整備份加密」，本輪完成評估，不宣稱交付加密檔案功能。

| 選項 | 對目前架構的影響 | 本輪取捨 |
| --- | --- | --- |
| 改用 SQLCipher | 改變 DB 驅動、檔案格式、部署及升級／復原驗證；不只影響下載 | 不為備份 UX 直接替換既有 SQLite 引擎 |
| 另做加密備份容器 | 可保留內部 SQLite，但須設計版本、獨立備份密碼、KDF 限制、nonce、驗證過的標頭、解密暫存與錯誤回復 | 可列後續選配，但先完成格式／威脅模型及跨平台驗收，不在本輪倉促加入 |
| 在外部安全儲存位置保存 SQLite | 不改應用格式；保護範圍取決於該工具及檔案被取出後的處理 | 目前仍須由使用者妥善管理，不能因此把 ProjMemo 標成完整備份已加密 |

未來若實作容器，需先決定獨立備份密碼與遺失政策，不能把保管庫解鎖金鑰存進備份、把 ZIP 壓縮等同加密，或擅自讓未設定保管庫的人無法備份。認證加密的 nonce／tag／associated data 與錯密碼、竄改、截斷、超限 KDF／檔案、暫存失敗及舊 SQLite 還原相容性都須另驗證。

以上屬本專案的設計評估，不表示已實作任何新密碼格式。技術依據：認證加密及 nonce／驗證錯誤規範見 [Cryptography AEAD 官方文件](https://cryptography.io/en/latest/hazmat/primitives/aead/)；SQLCipher 的全資料庫加密設計見 [SQLCipher 官方設計](https://www.zetetic.net/sqlcipher/design/)。
