# 備註分頁與草稿邊界（R05）

## 目前行為

內容頁預設只讀取 20 筆備註，可選 10／20／50，依 id 由新至舊。`notes_page`／`notes_size` 在 URL 保留頁次，獨立 COUNT 提供總數，導覽與區塊重複計數均保留；非法參數回預設，深頁及刪除後頁數縮減會夾到合法範圍。空清單仍可新增，不提供「全部」以免重新載入大量 HTML。

`services/workspace.py` 是 UI 專用查詢，不建立裁切版 `ProjectData`。完整專案、普通／敏感 Markdown／PDF 及 SQLite 備份維持完整資料；普通查詢不讀密文或解密。`project_related()` 只共用其他內容投影，完整 `project_detail()` 另載入全部備註。schema 仍為 v3，無新資料表或 WAL 更動。

## 原生與局部更新

- 原生 GET 表單與前／後／首／末頁連結不依賴 JS；關閉 JS 仍可逐頁瀏覽與提交，表單附帶安全頁次欄位。伺服器端保護仍有效，離開草稿提示需 JS。
- 啟用 JS 時，同一 GET 路徑攜帶 `X-ProjMemo-Fragment: notes` 回傳共用的備註 section。沒有新增寫入 API；回應禁止快取並區分 fragment／Cookie。
- 確認捨棄只針對將被替換的備註草稿；取消保留 DOM。網路／503／不正確回應／10 秒逾時均保留目前內容、頁次與所有草稿，提供明確的整頁回退連結，不自動跳轉。
- 成功後只換備註 section 的 children，保留 section 本身、其他四區的 DOM／草稿／密碼到期計時器；全頁跳轉回退仍由全頁草稿政策保護。請求期間又修改備註，提交替換前再次確認。
- 載入中停用分頁控制，阻擋重複請求；換頁後聚焦備註標題並更新總數與 URL。卡片／明細不重新複製節點。新節點僅綁定一次取消、摘要與程式碼複製；舊節點可回收，不重新啟動保管庫計時器。
- 新增備註回到第一頁，編輯／刪除保留當頁；深頁欄位錯誤依實際備註排名重新開啟正確表單。資料在其他視窗增刪時頁次可能移動，UI 有說明，不宣稱跨請求一致快照。
- 程序重啟會使 CSRF／送出識別／保管庫 session 失效，應先重新整理取得新頁面；不自動重播寫入或保存密碼。

## 可重跑量測

`.venv\Scripts\python.exe -X utf8 scripts/benchmark_r05.py` 只使用 TemporaryDirectory 假資料，完成後移除，不讀正式 DB。同一版模板比較完整內容渲染與 UI 投影；不是舊版本逐 byte 還原，也不是使用者機器的一般延遲保證。

1,000 筆、20 筆頁的 HTML 約減少 97%。暖機樣本 UI request 約 73 ms、fragment 約 52 ms，完整模板渲染約 2,471 ms；多項測試同時執行會影響時間，傳輸量與載入筆數才是可重現的主要差異。

隔離瀏覽器 12 組矩陣確認 1,000 筆、兩語／兩模式／10／20／50，另驗證最末頁、焦點、備註草稿保留／捨棄、其他區塊草稿、斷線重試及局部載入後編輯儲存；10 筆畫面約 1,084 DOM 元素、20 筆約 1,801（依內容與 code toolbar 而變）。Python 另驗證空清單、參數界線、刪除夾頁、深頁錯誤與 1,000 筆完整匯出；Node 驗證網路／格式錯誤及慢請求期間新草稿不丟失。這不替代 R06 真正 Windows 125%／150% 的未完成驗收。
