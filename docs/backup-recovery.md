# 備份與復原操作

ProjMemo 目前是本機單程序個人版。請使用單 worker，不要同時啟動兩個程式共用同一份資料庫；程序內保護不會協調其他程式或直接操作 SQLite 的工具。

## 一般備份與還原

1. 在「資料備份」下載完整 SQLite 快照。實際密碼是密文，其他專案／帳號資料為明文，主密碼與解密金鑰不在備份內。
2. 選擇先前的 ProjMemo 備份並按「預覽備份」，比較目前／備份的版本、數量、保管庫與匯出設定。上限 100 MB；驗證結構、資料版本、關聯、保管庫參數與密文格式，但不解密或驗證原主密碼，亦不立即取代資料。
3. 勾選替換確認並輸入 `RESTORE`。系統會等已接納的作業完成，保存還原前快照，確認資料未在預覽後變更，才撤銷解鎖、替換、初始化並驗證。等待超過 10 秒時取消此次還原，請稍後重試；還原中的新請求回覆 503。10 分鐘過期、重啟、已用過的確認或資料已變更須重新預覽；取消預覽會移除暫存上傳。
4. 成功後可下載還原前快照，需要密碼時以備份所屬的原主密碼重新解鎖。

支援的舊版備份（v0／v1／v2／v3）會在替換後進行逐版 schema 升級，升級前另外保存 `backups/migrations/` 快照。最新版為 v4（八張業務表、遷移紀錄表、七個量測索引與生命週期索引），版本／紀錄／生命週期欄位或必要索引定義不符的檔案在替換前拒絕。升級細節與啟動失敗的離線復原見 [SQLite 結構升級與復原](database-migrations.md)。

備份包含使用中、已封存及垃圾桶專案；還原會保留其分類。備份頁「自動復原點」合併列出最近 10 份還原前與永久刪除前快照，檔案不會自動刪除。刪除前快照使用 `projmemo-pre-delete-*.sqlite3`，回復的是整個資料庫，專案先回垃圾桶，再逐一復原。這不是單一專案合併或安全抹除；說明見 [專案生命週期](project-lifecycle.md)。

「復原點保留策略」預設全部保留，自訂數量／天數只用來挑選候選；必須先預覽、勾選及輸入 `DELETE` 才執行永久清理，不碰遷移快照。清理前請另存需要的副本；錯誤時核對已刪除及未清理筆數，不能假定整批已回復。政策檔不含在 SQLite 下載中、不隨還原改寫。詳細範圍、暫存清理、舊 API 相容性及尚未實作的全檔加密見 [備份預覽與保留策略](backup-experience.md)。

## 發生錯誤時

- **驗證失敗或快照未建立**：資料尚未替換，修正檔案或磁碟／權限問題後再試。
- **「已使用還原前備份回復」**：原資料已回復；保管庫需重新解鎖。下載快照妥善保存，再調查失敗原因。
- **「自動回復未能完成」**：程式阻止一般資料操作，不能把現有資料視為完整。備份頁及 `/settings/backup/files/...` 仍可使用，先下載還原前備份。

## 自動回復失敗的人工處理

1. 下載錯誤頁提供的還原前備份，確認有檔案；勿清除 `backups/` 目錄。
2. 完全停止 ProjMemo（含 reload 子程序及其他 worker）。確認沒有其他程式持有此資料庫。
3. 將目前資料庫及若存在的同名 `-wal`、`-shm` 檔案一起複製到另一個復原暫存目錄保留；勿把舊 sidecar 混用到新資料庫。
4. 在另一個空目錄放置下載的還原前 `.sqlite3`，先以 `PROJMEMO_DB_PATH` 指向此檔案啟動單一 ProjMemo，檢查專案與帳號、以原主密碼解鎖確認資料。
5. 驗證成功後可繼續使用此新路徑；若要回到舊路徑，先再次停止程式，再由熟悉 SQLite 的操作人員完成離線替換並移開舊 sidecar。保留所有復原副本，確認後再決定清理。

重啟會清除程序內的阻止狀態，因此不要只重啟便假定資料已修復。本流程保障應用程式正常執行時的排他與失敗回復，不等於斷電／程序強制終止的全套災難復原；操作前仍應保有獨立備份。
